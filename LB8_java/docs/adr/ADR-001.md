# ADR-001: Перенесення бізнес-логіки розрахунку вартості проживання в доменну сутність Booking

## Статус
Прийнято (Accepted)

## Контекст
У вихідному коді (`LegacyHotelManager`) обчислення вартості проживання, додаткових послуг (сніданки, парковка) та туристичного збору виконувалося в монолітному сервісі через пряме зчитування полів. Це призводило до Anemic Domain Model (анемічної моделі) та високого зачеплення (CBO).

## Рішення
Згідно з патерном GRASP **Information Expert**, ми перенесли обчислення вартості безпосередньо в сутність `Booking`, яка володіє даними про ночі, сезон та послуги. Для розрахунку сезонного коефіцієнта та послуг використано поліморфізм (**Polymorphism** та **Protected Variations**).

## Наслідки
- **Позитивні:** Знижено зачеплення сервісу з деталями кімнати; інкапсульовано формулу розрахунку; підвищено згуртованість (High Cohesion) доменної моделі.
- **Негативні компроміси:** Зросла кількість невеликих класів-стратегій.
