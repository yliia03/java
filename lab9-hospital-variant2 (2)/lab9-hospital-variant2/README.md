# Лабораторна робота №9. Породжувальні шаблони: Singleton, Prototype, Object Pool

Варіант 2 — Обласна лікарня. Мова: Java.

## Запуск

```bash
mkdir -p out
javac -encoding UTF-8 -d out src/hospital/*.java
java -Dfile.encoding=UTF-8 -Dstdout.encoding=UTF-8 -cp out hospital.Main
```

Приклад журналу — у `run-log.txt`.

## Розподіл ситуацій і вибір шаблонів

| № | Ситуація | Шаблон | Чому |
|---|----------|--------|------|
| 1 | Приймальне й профільні відділення мають працювати з єдиним реєстром ліжок; окремі копії реєстру дають подвійне призначення ліжка, а завантаження фонду дороге | **Singleton** (`BedRegistry`) | Потрібен рівно один екземпляр і глобальна точка доступу |
| 2 | Плани лікування однотипних пацієнтів майже однакові, складання за протоколом дороге, кожному пацієнту потрібна власна змінювана копія | **Prototype** (`TreatmentPlan`, `PlanTemplateRegistry`) | Новий об'єкт дешевше отримати клонуванням готового, ніж створювати з нуля |
| 3 | Апаратів УЗД мало, підключення й калібрування дороге, апарат після обстеження можна використати знову | **Object Pool** (`UltrasoundPool`) | Обмежений дорогий ресурс, який видають і повертають |

> Опис трьох проблемних ситуацій варіанта 2 було надано лише у вигляді опису домену, тому ситуації
> виведено з його сутностей (реєстр ліжкового фонду → Singleton, план обстеження й лікування →
> Prototype, апарат УЗД → Object Pool). Якщо в методичці сценарії інші, потрібно лише підправити
> методи `Main.situationN...`.

## Питання до захисту

- **Чому Singleton через lazy holder, а не `synchronized getInstance()` чи enum?** Клас-холдер завантажується JVM лише при першому зверненні, ініціалізація потокобезпечна без блокувань; enum-Singleton теж потокобезпечний, але створюється при завантаженні класу й не дає окремо контролювати ліниву важку ініціалізацію та її помилки; `synchronized` на кожен виклик зайвий. Методи `admit`/`discharge` синхронізовані, бо стан реєстру спільний.
- **Чому в `TreatmentPlan` глибока копія?** Списки аналізів і призначень змінні; поверхневе копіювання дало б спільні списки, і виправлення в плані одного пацієнта псувало б типовий план та плани інших.
- **Чим Object Pool відрізняється від Singleton?** У пулу кілька однотипних об'єктів, які видаються у користування й повертаються; обов'язковий `reset()` перед поверненням, щоб наступний пацієнт не отримав чужий профіль налаштувань.
- **Що буде, якщо всі апарати зайняті?** `acquire` повертає `Optional.empty()`, відділення очікує й повторює спробу після `release`. Можливе розширення: блокуюче очікування з тайм-аутом.
